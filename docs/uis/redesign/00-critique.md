# Knibbler UI critique

SEN-52 · 2026-10-25. Input: every page and component in `apps/web/src`, plus screenshots of every live state on local dev with real data (Home, Teaching Profile, new Request, clarification, Starting Level check, generating, failed, cancelled, Reading, Quiz, Course complete).

The short version: the app works, but it talks like the database, looks like an admin panel, and makes the Learner press a button for every step the server needs. The UI shows the pipeline instead of the person.

---

## 1. The root problem: the app speaks its own internal language

The domain glossary (`CONTEXT.md`) is good for engineering. It was copied into the UI word for word, with the Capitals. Users never asked to learn our nouns.

| On screen now | Why it hurts | Say instead |
| --- | --- | --- |
| **Course Request**, "New Course Request", "Save Course Request" | Sounds like a support ticket or a form you file and wait on. Nobody "requests" a course from a friend. | "What do you want to learn?" · "New course". In-progress ones are just courses that are "being made". |
| **Learning Goal** | Jargon. Also asks the user to write in curriculum language. | "What do you want to be able to do?" |
| **Subject** (separate field) | School form. Two fields for one thought. | One question; the companion asks a follow-up if needed. |
| **Teaching Profile** | Reads like a profile *of a teacher*. It is the user's preferences. | "How you like to learn" |
| **Validity decision**: "The subject and Learning Goal describe a learnable corpus or legitimate capability." | A moderation verdict shown to *every* user on *every* Request, even when it passed. | Hide on pass. On reject, the companion explains kindly and offers the reframe. |
| **Starting Level check**, "diagnostic", "Retry diagnostic" | Medical and exam words, right before we promise it isn't a test. | "A few quick questions so I don't bore you" |
| **Course Blueprint**, "Design my Course Blueprint" | Architecture jargon. | "Here's my plan for you" · "Your plan" |
| **Lesson order: linear.** / **free jump** | Engineering terms. "free jump" means nothing to a learner. | "Step by step" / "Let me jump around" |
| **Workspace** (top-left, and the back button in Study) | It is a label, not a place, and it is where the logo should be. | The Knibbler mark. Back = "Home". |
| **Open items** | Jira. | Gone; Home covers it. |
| Status chips: PUBLISHED, COMPLETED, AWAITING YOUR CLARIFICATION, COURSE GENERATION FAILED, VALIDITY REVIEW PASSED | System states in shouting caps. "Published" means nothing to a learner — they didn't publish anything. | "Ready", "Finished", "Needs your answer", "Couldn't finish" — or no chip, just the companion's line. |
| "Completed" (disabled button) / "Mark complete" | Fine idea, cold wording. | "I've read it ✓" |
| Generated titles: "…Check", "Quiz: …", "Check Your Knowledge: …" | Three naming styles in two courses. | A generator naming rule (out of scope here, flag for content). |

**Rule for the redesign:** glossary words stay in code and docs. UI copy is written for a person, lowercase, in the companion's voice.

## 2. Defensive copy

Spec guardrails are pasted into the UI as disclaimers. Each one is true; together they make the product sound anxious and legal.

- Teaching Profile shows *two* disclaimers back to back: "They are not a test of intelligence, ability, or disability." and "This is not a test, a diagnosis, or a learning-style label." Saying "disability" and "diagnosis" puts those ideas in the user's head on a preferences screen.
- "Saving keeps this Request in your Library. You can then check its validity before Assessment; no Course will be generated by saving." — and two more variants of "saving alone does not generate a Course" on the next screen.
- Starting Level check: "It is not a Quiz, not a grade, and not a test of intelligence."
- New Request: "Your Teaching Profile guides how future Lessons are taught, not your Starting Level." (true, irrelevant to the user at that moment).
- A generated Reading ends with "What this Lesson is not … Opening it was not completion." The generator is echoing spec language into lesson content.

**Rule:** keep the guarantee, drop the disclaimer. Say it once, warmly and positively ("No wrong answers here — pick *not sure* whenever you're not sure").

## 3. UX problems, worst first

1. **Making a course is a chain of buttons the server needs, not the user.** Save Course Request → "Check request" → "Start the check" → 8 questions → "Looks right" → "Design my Course Blueprint" → Approve. "Save" visibly does nothing; the user then has to *ask* for a validity check. Validity and Blueprint prep should just happen after the user answers.
2. **The Request screen is an audit log with the action at the bottom.** Every past step stacks on top: Subject, Learning Goal, Validity decision, the full six-card Blueprint, "Lesson order: linear." In the generating state the only live information ("Writing Lesson 3 of 6") is a grey line ~1,200px down the page. Current step must be the focus; history should recede. (A chat-like flow does exactly this: history scrolls up, the live prompt sits at the bottom.)
3. **Home is an undifferentiated pile.** 11 identical cards; 9 are failed, cancelled, or stalled Norse-mythology duplicates, one is finished, one is the course actually in progress. No "continue where you left off", no grouping (learning / being made / finished / stuck), no archive or delete. The sidebar's Open items repeats the same list in full. A test Request with an explicit title sits second in the sidebar permanently.
4. **Failure copy contradicts itself and leaks internals.** "We couldn't write the Lesson 'The Primordial Void…' so that it passed our quality checks. You can start a new Course Request from Home." — directly above a **Retry** button. The user can't tell what Retry will do, whether it will fail again, or whether it's their fault.
5. **Waiting is dead air.** Generation takes minutes; the screen gives one grey sentence, no progress bar, no estimate, nothing to do. "You can close this page" is the most useful line. This is the single biggest place a companion earns its keep.
6. **Study chrome fights reading.** "Workspace" as the back link; the header shows "The square knot · 1 / 3" with no label; Lessons panel hidden by default so there's no sense of where you are; reading text runs edge to edge (~150 characters per line at 1440px, double the comfortable 65–75); 14px body for long-form reading; no reading progress; "Completed" (disabled) and "Next Lesson" are two pale-blue buttons stacked across a divider.
7. **Quizzes feel like a tax form.** All questions on one long page, full-width radio rows in boxed fieldsets, Submit disabled with no hint why. One question at a time with a gentle reaction fits learning better (the per-item feedback mode already exists).
8. **Course complete has no moment.** Finishing a course looks like a receipt. "Back to Home" is the primary action; "Review Lessons" is a text link; there's no suggested next step (go deeper, related course, share).
9. **Teaching Profile is eight boxed cards with all-caps labels**, a "VIEWING" badge, and three overlapping buttons (Edit / Reassess / Reset to defaults). It should be a short conversation (SEN-56) and afterwards a one-line summary ("short lessons · examples first · feedback after each question").
10. **First run is a dead end.** Clicking New Course Request before the profile exists shows "Save a Teaching Profile before you request a Course." and a button elsewhere. Should flow straight into those questions.

## 4. Visual problems

- **No brand.** No logo, no colour identity, no illustration, no motion. "Workspace" sits where a logo goes.
- **Primary colour reads as disabled.** Buttons are a desaturated pale blue (`oklch(0.8 0.04 230)`); real disabled buttons (Submit, Next) are a slightly greyer pale blue. You can't tell them apart at a glance.
- **Everything is the same box.** Library item, Blueprint lesson, profile answer, quiz option, quiz question: same border, radius, weight. No hierarchy, so nothing is important.
- **Shouting micro-labels everywhere:** PUBLISHED, OPEN ITEMS, QUESTION 1 OF 8, INSTRUCTIONAL LANGUAGE, THE NORSE COSMIC CYCLE.
- **Layout is inverted.** Forms and lists sit in a narrow centred column with huge empty gutters; the one place that needs a narrow column (reading) goes full width.
- **Default type.** System stack, small sizes, no distinction between UI text and reading text.
- **Errors are red text only**, no icon, often far from what caused them.

## 5. Content the user sees (not design, but it shapes the feel)

- Lesson goals are written as learning objectives ("Recall the primordial void Ginnungagap and the first being Ymir, and apply that knowledge to a creation scene"). Right for the generator, cold for the learner. Show a friendly "you'll learn…" line and keep the objective behind it.
- Library titles come from the raw Subject, so seven cards say "Norse mythology" and one says "greek gods" in lowercase. Use the Blueprint title once it exists.

## 6. Worth keeping

- Dark-by-default and calm.
- "I don't know" in the Starting Level check, and the honesty behind it.
- Readings with numbered sources.
- Generation progress names the lesson being written.
- Rejected requests keep history and offer a reframe instead of a dead end.

## 7. What this means for the redesign

- **Chat-*like* flow** (scripted prompts and tap-to-answer chips, no free chat). Fixes 3.1, 3.2, 3.5, 3.9, 3.10 almost by construction: the server steps become the companion's turns, history scrolls away, the live step is always at the bottom.
- **A companion owns the voice.** Disclaimers become one friendly line. Failure becomes "that one didn't come out right — want me to try again?".
- **Spec §3 rules this breaks:** "The Course Guide is ordinary page copy … Not a chat, not a character, not a side rail." Recorded in `docs/spec.md` once the direction is chosen.
- **Theme:** dark, purple + light blue, soft glow used sparingly (the companion, the active step, a finished course), never on body text.
- **Next:** pick the companion (`01-companions.html`), then mock the full flow across Home, new course, plan review, waiting, Reading, Quiz, and Course complete.
