# The subject check asks once, replaces the subject with the Learner's pick, and never blocks a Request

**Why:** The reading the Learner picks becomes the Request's subject, and the subject as typed stays on record. That way every later stage reads the settled subject with no extra wiring. **None of these** takes a short typed answer, which is used as written and not checked again. Validity still judges it like any subject. A failed or invalid Luna call goes straight on to Validity with the subject as typed.

We turned down a second round, and re-checking a typed answer. Both add a loop and a status for a case Validity's clarification already covers. We also turned down holding the Request when the check fails, because a cheap triage step should never be why a Learner is stuck.

**What it costs:** a vague typed answer reaches Validity unsettled. If the triage model is down, ambiguous subjects slip through as they do today.
